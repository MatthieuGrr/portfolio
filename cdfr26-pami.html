Contexte : la Coupe de France de Robotique

La Coupe de France de Robotique est la plus grande compétition de robotique amateur en Europe (~100 équipes). L'édition 2026 sur le thème "Winter is Coming" demandait aux robots de jouer le rôle d'écureuils autonomes : collecter des noisettes et les dissimuler avant le retour des humains. Les PAMIs (Petits Actionneurs Mobiles Indépendants) sont des robots secondaires qui quittent la zone principale en fin de match pour marquer des points supplémentaires.

Objectifs du projet

  • Robot compact et autonome : Navigation par waypoints sans infrastructure externe
  • Architecture temps réel robuste : FreeRTOS multi-tâche sur ESP32-S3
  • Interface de supervision complète : GUI Python + API REST + WebSocket
  • PCB dédié : KiCad 9 avec tous les composants intégrés
  • Open source : Firmware et hardware publiés pour la communauté robotique

PCB KiCad 9

Le PCB a été conçu sous KiCad 9 en intégrant tous les composants nécessaires sur une carte compacte adaptée au gabarit du robot. Le dossier hardware/PCB_Pami_V2/ est auto-suffisant : toutes les empreintes et symboles non-standard sont inclus, permettant une ouverture directe dans KiCad 9 sans dépendances externes.

  • ESP32-S3-DevKitC : Carte de développement montée sur le PCB via connecteurs
  • DRV8833 : Driver pont H double pour commander les deux moteurs DM996 modifiés avec encodeurs
  • Servo SG90 (GPIO 14) : Servo standard dédié aux actions de jeu (balayage 60°–120° ou position fixe)
  • ICM-20948 : IMU 9 axes (accéléromètre, gyroscope, magnétomètre) via I2C
  • VL53L0X : Capteur de distance Time-of-Flight (détection obstacles/bord de table)
  • TCS34725 : Capteur couleur RGB présent sur le PCB — non implémenté dans le firmware actuel (intégration possible)
  • SSD1306 : Afficheur OLED 128×64px pour le débogage en live
  • Boutons physiques : 3 boutons (gauche/milieu/droite) pour la sélection d'équipe (bleu/jaune) et le démarrage de mission
  • Connecteurs encodeurs : Interfaçage direct des roues codeuses quadrature (20 CPR × 4 = 80 ticks/tour)

Conception mécanique

La mécanique a été modélisée sous OnShape en conception paramétrique, permettant des itérations rapides entre les cycles de prototypage et de validation. Le châssis imprimé en 3D intègre les emplacements des roues, du PCB et des capteurs dans un encombrement minimal pour respecter les contraintes de taille de la compétition.

  • Transmission différentielle : Deux moteurs DM996 modifiés avec encodeurs quadrature, commandés via le DRV8833
  • Roue folle avant : Troisième point d'appui pour la stabilité
  • Montage capteur ToF : VL53L0X orienté vers l'avant pour la détection de bord de table, des autres robots et la pause automatique de mission
  • Accès direct PCB : Conception modulaire pour faciliter les remplacements

Architecture firmware

Le firmware est développé sur ESP-IDF v5.x avec FreeRTOS, structuré en modules indépendants pour faciliter le développement et les tests. Chaque module encapsule une responsabilité précise, communiquant via des queues et des semaphores FreeRTOS.

Structure modulaire du projet

  • motion/ : Contrôle mouvement — commandes cmd_vel, exécution de waypoints, contrôleur de point décalé (offset point controller)
  • localization/ : Odométrie à partir des encodeurs, fusion avec l'IMU ICM-20948 pour un suivi de position fiable
  • drivers/ : Abstraction matérielle — DRV8833 (LEDC PWM), encodeurs quadrature, servo SG90, VL53L0X, SSD1306, MPU6050
  • sensors/ : Drivers IMU (composant dédié icm20948) et capteur ToF
  • net/ : Wi-Fi mode STA avec IP statique par robot_id, serveur HTTP pour l'API REST
  • ws/ : Serveur WebSocket pour les logs en temps réel et la télémétrie
  • mission/ : Séquenceur de missions — chargement et exécution de waypoints
  • config/ : Configuration persistante via NVS (Non-Volatile Storage)
  • ota/ : Mise à jour Over-The-Air pour le déploiement en compétition

Navigation par waypoints

Le PAMI navigue de manière entièrement autonome en suivant une liste de waypoints (x, y) définis dans la mission. La loi de commande retenue est un offset point controller : le contrôleur calcule la vitesse d'un point virtuel P situé à 50 mm devant le robot, puis en déduit les commandes (v, ω) par inversion cinématique. Cette approche produit des trajectoires fluides sans oscillations, même lors de l'enchaînement de waypoints intermédiaires à vitesse maximale.

  • Odométrie encodeurs : Calcul de (Δx, Δy, Δθ) depuis les impulsions quadrature des deux roues (80 ticks/tour, Ø 65,1 mm, empattement 106,8 mm)
  • Fusion IMU : Le gyroscope et le magnétomètre de l'ICM-20948 corrigent le cap odométrique — la fusion est effectuée directement sur la carte par le DMP de l'ICM-20948
  • Commande moteurs via DRV8833 + LEDC : Vitesse [-200, 200] mappée en PWM 10 bits avec zone morte de 145 ticks
  • Sécurité ToF : Pause automatique de la mission si obstacle détecté à moins de 150 mm (seuil configurable)
  • Tolérance d'arrivée : 80 mm en position, enchaînement fluide sur les waypoints intermédiaires (vitesse maximale maintenue)

Interface réseau : API REST + WebSocket

Le robot se connecte en mode STA à un réseau Wi-Fi existant avec une IP statique calculée depuis son identifiant : le robot N obtient automatiquement l'adresse 192.168.0.(109+N). Il expose ensuite une API REST et un serveur WebSocket pour le contrôle et la supervision.

  • Wi-Fi mode STA + IP statique : Jusqu'à 6 robots sur le même réseau, chacun adressable depuis la GUI Python ou depuis l'UI du SSD1306
  • API REST : Commandes de vitesse, démarrage/arrêt des missions, lecture des capteurs, configuration des paramètres, OTA
  • WebSocket télémétrie : Stream continu de position, vitesses et état capteurs à 10 Hz pour la supervision en temps réel
  • WebSocket logs : Miroir des logs ESP-IDF dans la GUI Python pour le débogage sans câble série
  • OTA via HTTP : Upload du nouveau firmware depuis la GUI sans démonter le robot — essentiel pour les corrections rapides en compétition

Outils Python de supervision

Un écosystème d'outils Python accompagne le firmware pour le développement, le débogage et la préparation des missions en compétition.

robot_gui.py — Interface de contrôle complète

GUI graphique offrant une vue unifiée de l'état du robot : position estimée, vitesses, valeurs capteurs en temps réel, commandes manuelles et lancement de missions. Communique via l'API REST et le WebSocket du firmware.

waypoint_editor.py — Éditeur de trajectoires visuel

Outil interactif permettant de dessiner les trajectoires du PAMI directement sur une représentation de la table de compétition. Les waypoints créés sont sérialisés et automatiquement injectés dans le code source de la mission pour le prochain flash.

robot_client.py — Client REST/WebSocket

Bibliothèque Python réutilisable encapsulant toutes les interactions avec l'API du robot. Utilisée à la fois par la GUI et les scripts de test automatisés.

Open Source

L'ensemble du projet — firmware, PCB et outils Python — est publié en open source pour que d'autres équipes puissent s'en inspirer ou réutiliser directement les composants. Le dépôt inclut une documentation complète et un dev container Docker pour un environnement de développement ESP-IDF reproductible.

  • Firmware : Source complète ESP-IDF avec tous les modules
  • PCB KiCad 9 : Schématique, routage et fichiers de fabrication
  • Outils Python : GUI, éditeur de waypoints et client REST
  • CAO Onshape : Modèle 3D paramétrique du châssis
  • Documentation : Guide de mise en route complet
  • Dev container : Environnement Docker avec ESP-IDF préconfiguré
